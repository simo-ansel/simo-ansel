## About me

I'm a Computer Science student at the University of Parma and a software developer
who learns by building.

I don't tie myself to a single area: so far I've written a desktop application for
archiving paper documents, data pipelines in Python, security tooling for Linux servers
and small web apps. What they have in common is the approach — understand the problem
first, pick tools I can actually reason about, and leave behind something documented
that someone else can run.

I'm finishing my degree and open to internships and junior roles.

## How I build

Most of my projects start from a real problem or from something I want to understand
properly. I'd rather know a few tools well than list many I've only touched.

A few habits I try to keep in every repository:

- **Safe by default.** Tools that modify a system check before acting and can be undone.
- **Readable over clever.** Small modules with one responsibility each, named so the code
  explains itself.
- **Documented enough to run without me.** Every README covers setup, usage and the errors
  someone is likely to hit.
